# SpineSlim AI 智能体检功能设计文档

> 版本：V1.0 规划稿
> 状态：分阶段实施中
> 原则：本地检测优先、AI 可选、只检查不擅自修改原文件。

### 当前实现进度

已接入桌面端真实目录扫描与拖入、任务取消、文件数量与体积统计、规则状态、按严重程度和关键词筛选、问题所在目录打开，以及 JSON / HTML 报告导出。当前规则检查精确重复、Spine Atlas 贴图、BMFont 页图片、GLTF 外部依赖、图片尺寸与透明边距、文件体积与格式签名、命名和 Spine JSON 基础结构。检测结果来自本地规则，不调用模型；报告只含相对文件路径。

已提前接入可选 AI 对话：完成体检后，用户可用设置中保存的模型提问。发送前能查看精简报告摘要；默认只发送数量、体积、问题类型和等级，主动勾选后才附带有限的相对文件名及问题证据。原始素材和 API Key 不经过前端请求体；密钥从系统凭据库读取。AI 返回的内容是建议，不会修改文件。模型服务可能收费，且发送时需要联网。

后续按 V1.0 继续补充疑似未使用资源、引用关系图及更细的扫描覆盖说明。V1.1 再做现有处理模块联动；AI 对话后续可增加问题级上下文与方案确认。未完成的规则不得在界面宣称已检查。

## 1. 产品定位

将「AI 智能体检」建设为游戏资源质量检查中心，而不是 AI 聊天页面。用户选择资源目录后，系统完成扫描、规则检查、风险分级、报告生成，并引导用户使用 SpineSlim 现有工具修复。

每项问题应回答：涉及哪个文件、判定依据是什么、可能造成什么影响、如何处理、能否跳转现有工具。

第一版闭环：**检查 → 报告 → 引导修复 → 重新检查**。

## 2. 版本规划

| 版本 | 目标 | 范围 |
|---|---|---|
| V1.0 | 本地资源体检 | 文件扫描、检测规则、风险列表、报告导出、真实进度 |
| V1.1 | 优化工具联动 | 从问题详情定位文件、跳转已有处理工具、修复后复检 |
| V1.2 | 深化 AI 分析 | 在已接入的 OpenAI 兼容 / Anthropic / Gemini 对话上增加问题级上下文与优化方案确认 |
| V2.0 | 智能修复助手 | 批量处理、变更预览、用户确认、备份与结果验证 |

> V1.0 不依赖网络、API Key 或大模型。AI 不负责确定性的文件检测。

## 3. V1.0 功能范围

### 3.1 资源导入与识别

- 支持拖入目录、手动选择目录。
- 递归遍历文件，记录相对路径、扩展名、实际格式、字节大小及可获取的元数据。
- 建立资源引用索引，优先复用 SpineSlim 已有解析器。
- 对无法解析的文件记录原因，不中断整个扫描。

| 类型 | 第一版范围 |
|---|---|
| Spine | JSON、Atlas、关联纹理的基础结构与依赖检查 |
| 图片 | PNG、JPG、WebP 的尺寸、体积、透明通道检查 |
| 图集 | Atlas 及关联纹理检查 |
| BMFont | FNT 及关联纹理检查 |
| 音频 | MP3、WAV、OGG 的基础格式、大小检查 |
| 视频 | WebM 的基础格式、大小检查 |
| Rive | RIV 基础文件检查 |
| 3D | GLB、GLTF 基础结构与可解析依赖检查 |

不承诺所有格式的深度兼容；应在报告中标注检测覆盖范围。

### 3.2 检测规则清单

| ID | 规则 | 检测方法 | 输出 |
|---|---|---|---|
| R01 | 精确重复文件 | 文件大小初筛，再以 SHA-256 确认 | 重复文件组及可节省空间估计 |
| R02 | 疑似重复资源 | 文件名、尺寸、大小等特征筛选 | 候选组，需人工确认 |
| R03 | 疑似未使用资源 | 从可解析入口建立引用图，检查不可达文件 | 候选文件及分析局限 |
| R04 | 缺失依赖 | 检查 Atlas、FNT、GLTF 等引用路径 | 缺失路径和引用源 |
| R05 | 图片尺寸异常 | 按可配置阈值检测宽高 | 文件尺寸及阈值 |
| R06 | 透明边距过大 | 分析 Alpha 非透明区域包围盒 | 四边边距及占比 |
| R07 | 文件体积异常 | 按资源类型与阈值比较 | 实际大小及阈值 |
| R08 | 命名规范 | 空格、特殊字符、大小写冲突等 | 命名问题及建议 |
| R09 | Spine 关联检查 | Skeleton、Atlas、纹理的基础引用核验 | 不匹配或缺失项 |
| R10 | BMFont 完整性 | 字符定义、页信息和纹理引用 | 异常字符或缺失纹理 |
| R11 | GLTF 外部依赖 | 检查 buffers / images 的本地 URI | 缺失的缓冲文件或纹理 |
| R12 | 资源统计 | 按类型、数量和体积聚合 | 总览与分布 |
| R13 | 文件格式异常（后续） | 文件签名与扩展名比对（适用格式） | 不一致信息 |

**误判约束：**

- 未使用资源只能标为「疑似」，运行时动态引用可能无法静态分析；扫描入口和支持的引用格式须可追溯。
- 视觉相似不等于重复；只有内容 Hash 一致才能判为精确重复。
- 图片大、文件大不等于运行时性能差，只能输出资源优化建议。
- 不可解析或未覆盖的格式标记为「未检查」，不得标为「通过」。

### 3.3 结果分级

| 等级 | 含义 | 示例 |
|---|---|---|
| critical / 严重 | 明确影响资源可用性 | Atlas 缺少关联纹理 |
| warning / 警告 | 明确问题或较高风险 | 精确重复文件、命名冲突 |
| suggestion / 建议 | 可优化但不代表错误 | 透明边距过大 |
| passed / 通过 | 当前规则覆盖项未发现问题 | 已解析依赖完整 |
| unchecked / 未检查 | 解析失败、规则不适用或未覆盖 | 不支持的格式 |

## 4. 页面与交互设计

现有页面保留产品视觉风格，但缩小顶部演示区，把真实扫描结果作为主体。扫描完成后采用左右布局：左侧查看结果，右侧固定 AI 对话，滚动问题列表时仍可提问；窄窗口改为单列。页面结构：

1. 顶部：标题、当前模式（本地规则检测 / AI 深度分析）。
2. 导入区：目录拖入、选择目录、检测设置、开始检测。
3. 执行区：阶段进度、已扫描文件数、当前规则、取消按钮、可展开日志。
4. 左侧结果摘要：文件总数、严重问题数、警告数、建议数、未检查数。
5. 左侧结果列表：按等级筛选，支持搜索与定位。
6. 左侧问题详情：文件路径、判定依据、影响、建议、关联工具入口。
7. 右侧 AI 对话：扫描完成后显示，可查看并手动发送报告摘要。
8. 操作区：导出报告、重新体检。

### 4.1 任务状态

| 状态 | 说明 |
|---|---|
| idle | 等待选择资源 |
| scanning | 遍历目录并建立文件索引 |
| analyzing | 执行检测规则 |
| completed | 检测完成并生成报告 |
| cancelled | 用户主动取消 |
| failed | 无法继续的任务级错误 |

部分文件解析失败时继续执行，报告状态可为 `partial`。进度必须由真实任务驱动，不得以定时器模拟。无法准确估算总量的阶段可使用不确定进度指示。

### 4.2 问题详情

展示规则 ID、问题名称、严重等级、涉及文件（相对路径）、检测证据、影响说明、处理建议、可用工具入口。工具跳转时传递目标文件路径；第一版不自动改动源文件。

## 5. 技术架构

```text
Audit UI
   ↓
Audit Controller（任务调度、状态、取消、进度）
   ↓
File Scanner（遍历、识别、索引）
   ↓
Rule Engine（规则注册、执行、隔离错误）
   ↓
Report Builder（汇总、分级、导出 JSON / HTML）
   ↓
AI Analyzer（V1.2 可选，只读取报告摘要）
```

建议逻辑目录（实际落地前对照现有项目结构调整）：

```text
audit/
├── core/
│   ├── AuditController.ts
│   ├── FileScanner.ts
│   ├── RuleEngine.ts
│   └── ReportBuilder.ts
├── rules/
│   ├── duplicate/
│   ├── dependency/
│   ├── image/
│   ├── spine/
│   ├── bmfont/
│   └── naming/
├── types/
│   └── audit.ts
├── ai/
│   └── AIAnalyzer.ts
└── config/
    └── auditRules.ts
```

规则接口需要支持 `ruleId`、规则版本、适用类型、配置阈值、执行结果和错误隔离。大目录扫描应避免阻塞 UI；支持取消与合理的内存控制。

### 5.1 核心数据模型（示意）

```ts
type AuditSeverity = 'critical' | 'warning' | 'suggestion' | 'passed' | 'unchecked';
type AuditStatus = 'completed' | 'partial' | 'cancelled' | 'failed';

interface AuditIssue {
  id: string;
  ruleId: string;
  severity: AuditSeverity;
  title: string;
  description: string;
  files: string[];
  evidence: string[];
  suggestion: string;
  fixTool?: string;
  autoFixable: boolean;
}

interface AuditReport {
  version: string;
  createdAt: string;
  rootPath: string;
  totalFiles: number;
  totalSize: number;
  issues: AuditIssue[];
  durationMs: number;
  status: AuditStatus;
}
```

正式实现时补充规则执行记录、覆盖范围、跳过原因和错误明细。导出报告默认使用相对路径，避免不必要地泄露用户本机绝对路径。

## 6. V1.2 AI 分析设计

- 用户自带 API Key；支持 Base URL、Model、测试连接和启用开关。
- 优先支持 OpenAI 兼容接口，避免与单一模型厂商绑定。
- 只向模型发送必要的报告摘要，不默认上传原始图片、Spine 文件或完整目录。
- AI 负责解释检测结果、按优先级组织修复建议，不替代确定性规则判断。
- AI 返回内容明确标记为「AI 建议」，不能覆盖本地检测证据。
- AI 失败、超时或未配置时，本地体检仍可正常使用。
- API Key 使用系统安全存储，不明文保存于普通配置文件或日志。
- 请求前说明将向第三方服务发送哪些元数据。

V1.2 不实现 AI 自动删除文件、修改原始资源、多 Agent 协作或云端整目录扫描。

## 7. 开发执行方案

### 阶段一：基础框架

- [ ] 对照现有代码确认资源解析器、文件访问接口和 UI 组件可复用范围。
- [ ] 建立 Scanner、Controller、RuleEngine、ReportBuilder。
- [ ] 实现任务状态、进度、取消、错误隔离。

**验收：** 真实目录可正确统计数量、类型、大小；扫描不阻塞 UI；取消后不继续启动新规则任务。

### 阶段二：检测规则

- [ ] 完成 R01～R12；为每项规则准备正常、异常、边界样例。
- [ ] 处理引用关系和无法确认的动态引用。
- [ ] 统一等级、证据、建议、跳过原因。

**验收：** 样例集输出可复现；不会把无法确认的未使用资源判定为可安全删除；不支持的资源不显示为通过。

### 阶段三：UI 接入

- [ ] 用真实任务数据替换截图中的演示内容。
- [ ] 完成导入、进度、取消、状态、筛选、问题详情。
- [ ] 增加规则开关及阈值配置。

**验收：** 成功、部分失败、取消和任务失败均有正确反馈；不出现假进度、假日志、假检测结果。

### 阶段四：报告与联动

- [ ] 导出 JSON、HTML 报告。
- [ ] 从问题详情跳转现有资源处理工具。
- [ ] 修复后重新体检。

**验收：** 报告可定位问题及证据；工具跳转路径正确；重新扫描反映资源实际变化。

### 阶段五：AI 分析（V1.2）

- [ ] 模型配置、密钥安全存储和连接测试。
- [ ] 生成脱敏后的报告摘要。
- [ ] 展示 AI 解释与优化优先级。
- [ ] 处理超时、错误、无 Key 场景。

**验收：** 未配置 AI 时本地检测完全可用；AI 不直接修改文件；用户知晓第三方数据发送范围。

## 8. 明确不做

- 自动删除、自动覆盖源文件。
- AI 自主执行文件系统操作。
- 云端资源扫描与跨项目重复检测。
- 全格式深度解析承诺。
- 根据文件体积直接推断游戏运行性能。
- 缺乏可解释依据的 AI 综合评分。

## 9. V1.0 发布验收场景

用户拖入一个真实游戏资源目录，点击开始体检；软件识别资源、执行规则、展示真实进度与问题列表；用户可以定位异常文件、查看证据与处理建议、导出报告，并在修复后重新检测。全程无需联网、无需 API Key，且不会擅自修改原文件。

达到以上闭环即可发布 V1.0，不以接入大模型作为上线前提。
