# Spine 目录预览器设计方案

状态：第一批本地 Alpha 已开始实施，详见[本地测试记录](SPINE_VIEWER_LOCAL_TEST.md)。本文是目标设计，不代表所有功能或版本兼容已完成。

[验收方案](SPINE_VIEWER_ACCEPTANCE.md) · [Tauri 升级方案](TAURI_UPGRADE_PLAN.md)

## 1. 目标与范围

在现有 Tauri 2 + React + TypeScript 应用中增加独立「Spine 预览」模块。用户选择一个本地目录，即可浏览其中的 Spine 导出资源、切换动画和皮肤；不必打开浏览器，也不必先压缩或升级文件。

首期面向 Windows x64，提供中文和英文。预览与资源处理独立，可以打开任意目录，包括用户自行选择的处理输出目录；不自动绑定压缩任务，不做处理前后对比。预览只读，不改写源 JSON、二进制、Atlas 和纹理。

“多版本兼容”指按素材版本加载匹配的运行时，并经真实样例验证，不是修改 JSON 版本字段后交给同一个运行时。必须同时验证数据解析、动画语义和实际绘制。

## 2. 参考资料及采用方式

- 用户参考图一：大画布、网格背景、右侧参数、底部播放进度、皮肤与调试选项。
- 用户参考图二：选择目录/文件、拖放导入、本地处理、自动识别版本。
- 本机 `resource-manage/Editor.html`：已有 canvas 与右侧控制区、背景颜色、资源选择、播放/停止、暂停/恢复、场景缩放等交互。
- HTML 实际引用 `Editor_files/index.bundle.js.下载`（约 7.8 MB）。仅查看 HTML 无法确认它支持的运行时版本、完整实现或源码授权。
- 对配套 bundle 的初步检查发现 `@esotericsoftware/spine-pixi-v8`、`spine-core`、`SkeletonBinary`，以及独立的 Basis JS/WASM 转码器路径；说明可以参考 Pixi 渲染与二进制加载方式，但不证明历史版本都兼容。bundle 包含 Spine Runtimes License Agreement，精确依赖版本和分发条件仍须核对。

借鉴布局和操作逻辑；实施前再检查 bundle 中可复用的渲染方法、坐标处理及依赖版本。未经来源和许可确认，不直接复制整个 bundle，不引入其中的内网地址和远程脚本。截图上的“3.6 至 4.3”是参考产品的说明，不是本项目已验证的承诺。

## 3. 页面布局

沿用 SpineSlim 的浅色外壳、统一表单样式，画布默认深灰色。侧栏新增「Spine 预览」，首次进入为导入空态；选择目录后变为工作台。

```text
应用导航 │ 顶栏：目录名 / 选择目录 / 添加文件 / 刷新 / 扫描状态
         ├──────────────┬────────────────────────┬─────────────────┐
         │ 资源目录      │                        │ 当前资源         │
         │ 搜索 / 筛选   │                        │ 相对路径         │
         │              │       Spine 画布        │ 导出版本/运行时  │
         │ ▾ effects    │                        │ 动画 / 皮肤      │
         │   win [3.8]  │                        │ 速度 / 显示设置  │
         │   glow [4.2] │                        │ 调试 / 诊断      │
         ├──────────────┼────────────────────────┴─────────────────┤
         │ 资源数量      │ 播放/暂停 · 时间轴 · 时间 · 循环 · 适应画布 │
         └──────────────┴──────────────────────────────────────────┘
```

- 约 1440 px 宽时，目录栏默认 240 px，属性栏 280 px，画布占剩余空间；两侧可拖拽调整或收起。
- 在现有最小窗口 960 × 720 下，属性栏改为抽屉，目录栏可收起，保证画布及播放条可用；页面不产生整体横向滚动。
- 目录保留源层级，同名资源以相对路径区分。条目显示版本和状态：待加载、可预览、待匹配、缺文件、不支持、加载失败。
- 搜索按文件名和相对路径匹配；筛选全部/可预览/异常。目录很多时虚拟化列表，不同时解码所有资源。
- 空态主按钮「选择文件夹」，次按钮「选择文件」；可拖入目录或一组导出文件。明确提示需要骨架、Atlas 及 Atlas 引用的纹理。

## 4. 导入、扫描与资源配对

1. Rust 接收用户授权的目录或文件集合，建立当前会话的只读访问范围。
2. 后台递归扫描候选 `.json`、`.skel`、`.atlas` 与纹理文件，发送真实已扫描数量；支持取消。普通 JSON 不当作坏掉的 Spine 报错。
3. JSON 检查 Spine 骨架结构及 `skeleton.spine`；二进制使用有边界检查的头部探测器，返回原始导出版本与识别置信度，不用文件名猜版本。
4. 骨架优先关联同目录同名 Atlas；无同名时可推荐同目录唯一 Atlas，但须校验 attachment/region 和纹理引用。存在多个候选时进入「待匹配」，由用户选择，不能随便选第一个。
5. Atlas page 按 Atlas 所在目录解析，支持多页、共享纹理及相对子目录。保留原始路径大小写，缺失时指出具体 page 和解析后的相对路径。
6. 选择条目时才读取完整骨架并解码纹理。新选择使旧加载请求失效；过期请求不能覆盖当前画布。
7. 用户可以重新匹配 Atlas、补选纹理目录，映射仅保存在会话/本地设置中，不写回素材。

目录扫描不跟随符号链接/junction。Atlas 引用规范化后必须位于授权范围内；跨范围引用要求用户显式选择额外目录。禁止通过绝对路径、网络 URL、路径穿越读取任意文件。

首期单画布显示一个骨架，切换资源复用工作台；不做多骨架同屏编排。刷新重建清单并尽量保留仍有效的选中项；不自动监听整个磁盘。

## 5. 多版本运行时策略

### 5.1 目标矩阵

| 导出版本族 | 目标 | JSON | SKEL | 上线条件 |
| --- | --- | --- | --- | --- |
| 3.8 | 第一批优先 | 计划支持 | 计划支持 | 锁定匹配运行时，样例与参考播放通过 |
| 4.0 / 4.1 / 4.2 | 第一批优先，分别适配 | 计划支持 | 计划支持 | 每个版本族单独验证，不合并为一个 4.x 适配器 |
| 3.6 / 3.7 | 第二批兼容目标 | 待技术验证 | 待技术验证 | 确认可分发运行时、WebView2 可用及样例完整 |
| 4.3 及更新版本 | 后续扩展 | 不提前承诺 | 不提前承诺 | 运行时可获得、许可明确、单独验收后开放 |
| 缺版本 / 非法版本 / 更早版本 | 明确诊断 | 不静默猜测 | 不静默猜测 | 可提供受控手动选择；实际解析失败仍报错 |

版本按 major.minor 路由，运行时精确版本、包校验值和已验证导出补丁版本写入清单。若特定补丁需要例外，清单单独声明。兼容不能通过仅把版本文字显示正确来验收。

第一批通过不等于“全版本支持”。如果交付目标要求 3.6–4.2 全部支持，须等第二批也通过后才能按该范围验收。

### 5.2 渲染架构

```text
React 查看器：目录 / 播放条 / 参数 / 中文英文 / 错误提示
       │ typed commands + events
ViewerController：选择令牌 / 状态 / 资源配对 / 释放资源
       ├─ Tauri Rust：只读扫描、受限资源读取、版本探测
       └─ RuntimeRegistry → 当前版本 RendererHost → WebGL Canvas
```

- 预览不经过 Python 压缩后台，也不要求安装 ImageMagick、TexturePacker、Spine 编辑器或转换器才能播放普通 PNG/JPG/WebP 导出资源。运行时使用/分发的许可要求另行确认，不等同于要求安装编辑器。
- 各运行时单独打包与延迟加载，避免多个库争用全局 `spine` 或不同 Pixi 实例。优先采用模块隔离的版本适配器；旧运行时确有全局冲突时使用隔离 frame，frame 不提供任意 Tauri 调用能力。
- 统一接口：`load`、`play`、`pause`、`seek`、`setAnimation`、`setSkin`、`setSpeed`、`resize`、`fit`、`dispose`；各版本差异由适配器承担。
- RuntimeRegistry 声明支持版本、JSON/SKEL、调试能力、纹理格式及精确依赖版本。界面只展示当前适配器支持的选项。
- Runtime 和必要资源随应用打包，断网可用，不从 CDN 临时拉脚本。Rust 以会话资源 ID 提供受限读取；前端不获得任意磁盘访问权限，不使用公网服务传输素材。
- 首轮技术验证比较对应版本的官方 WebGL Runtime 与已有兼容方案，再确定依赖；不能因为名字叫 Spine Player 就假定支持所有历史版本。

## 6. 画布与播放行为

| 功能 | 交互与默认值 |
| --- | --- |
| 初次加载 | 默认循环播放第一个动画；无动画则显示 Setup Pose；有加载状态与错误占位 |
| 动画 | 显示原始名称和时长；切换从 0 开始；暂停状态下切换仍保持暂停 |
| 皮肤 | 默认 default 或第一个可用皮肤；切换重置必要插槽后重算当前动画姿态，防止残留 attachment |
| 时间轴 | 显示当前秒数/总时长；拖动时暂停，松开后恢复原播放状态；支持向前和向后定位 |
| 定位语义 | 从确定初始状态重建到指定时间；不能只修改 trackTime。4.2 物理约束等需按固定步进重放；拖动不触发业务音效/外部事件 |
| 播放 | 播放/暂停、回到开头、循环开关；非循环到末尾停住；速度 0.1–3 倍，默认 1 倍 |
| 视图 | 滚轮以指针为中心缩放；中键或空格+拖动平移；提供适应画布、重置视图和缩放百分比 |
| 初始构图 | 按动画采样包围盒适应画布并留约 10% 边距；限制采样耗时，回退当前姿态；不逐帧自动缩放导致画面跳动 |
| 极小特效 | 自动居中放大至可辨认，不照搬参考图中动画缩成一个点的效果；空/异常 bounds 使用安全默认值 |
| 背景 | 默认深灰；可选颜色、透明棋盘、网格、原点轴；背景仅改变预览 |
| Alpha | 优先读取可信 Atlas PMA 信息，无信息采用明确默认值并允许手动切换；显示当前状态，不依靠全局开关掩盖混合页问题 |
| 调试 | 骨骼、网格、包围盒等按适配器能力提供；普通用户默认关闭 |
| 资源信息 | 相对路径、导出版本、运行时版本、动画/皮肤数、Atlas 页数、纹理尺寸；诊断可复制 |

首期解码 PNG/JPG/WebP，包括多页 Atlas、旋转与裁切区域。`.basis`、KTX/KTX2 需要独立解码器和 GPU 格式能力验证，放入后续兼容任务；首期遇到它们显示明确不支持原因及转换建议，不能显示成缺图或成功。

## 7. 生命周期、性能与异常

- 状态：空闲 → 扫描 → 可选择 → 加载 → 可播放/失败；播放控制与加载状态分离。
- 取消扫描、切换目录、退出模块时撤销相应资源访问会话和过期请求，销毁纹理、动画帧循环、事件监听、Object URL 与运行时实例。
- 离开预览模块暂停渲染；恢复时保留有效的资源和视图状态。关闭窗口完全释放。
- 加载失败清理失败实例，保留目录可操作性，并显示重新加载/重新匹配入口，不让旧画面冒充新资源。
- GPU/WebGL 不可用、上下文丢失、内存或纹理尺寸超限都有独立提示；不无休止重试。
- 大目录分批返回结果；扫描与解析设置文件大小、纹理尺寸、总解码字节数上限。具体默认值在技术验证后按测试机实测冻结并写入验收报告。
- 错误有结构化代码、资源路径、原因和修复建议，切语言后状态与错误同步切换；原始工具/运行时异常作为诊断附文。

## 8. 本期与后续

本期：目录扫描与列表、文件导入、版本识别与匹配、第一批多版本播放、皮肤、时间轴、视图控制、诊断、双语、离线运行。

## 9. 实施顺序与交付门槛

1. 技术验证：收集有使用权的版本样例，确定 Runtime 依赖/许可，验证 3.8 和 4.2 的 JSON/SKEL、PMA、时间定位；建立完整版本矩阵与风险记录。
2. 目录基础：只读扫描、配对、异常状态、目录列表和选择令牌；先用元数据驱动 UI。
3. 第一条真实播放链：3.8 + 4.2、普通纹理、动画/皮肤/时间轴/适应画布，完成当前应用内联调。
4. 版本扩展：接入 4.0/4.1，逐项补齐差异；3.6/3.7 独立验证，不隐藏未通过的版本。
5. 验收收尾：离线、生命周期、性能、回归、依赖许可材料、全量双语与 Windows 安装环境测试。

先交付本地测试版，由用户用真实目录验收。未收到新的发布指令，不推送、不创建 GitHub Release。

SpineSlim 自有代码的 MIT 许可不覆盖第三方 Spine Runtime。正式分发前记录每个运行时来源、版本、对应许可文本及使用/再分发条件；若条件不满足，阻塞该运行时的分发，不能把修改后的包声明为全 MIT。
