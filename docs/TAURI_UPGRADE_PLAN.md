# SpineSlim 2.0 Tauri 升级方案

状态：设计草案，尚未实施。基线：Windows v1.1.0。目标：2.0 测试版通过验收后发布正式版。

[返回首页](../README.md) · [验收文档](TAURI_ACCEPTANCE.md)

## 1. 目标与范围

将 Python + Tkinter 界面迁移为 Tauri 2 桌面应用，保留已有资源处理能力，解决布局、工具配置、任务反馈和动态多语言问题。首期支持 Windows x64。

| 本次交付 | 后续独立交付 |
| --- | --- |
| Tauri 界面、Python 后台拆分和通信 | Spine 查看器 |
| Spine、UI 图片、视频三种处理模式 | macOS 适配、构建、签名和测试 |
| 工具检测、设置、配置迁移 | 多任务队列、自动更新 |
| 进度、日志、取消、结果反馈 | 更多主题和高级工作区 |
| 中文/英文、Windows 安装包与许可材料 | 其他语言 |

Spine 查看器仅预留模块边界，本次不接入 Spine Runtime。后续第一版查看器作为独立模块支持导入和播放，不与压缩结果联动，不做处理前后对比。正式可用前不展示不可操作的导航入口。

## 2. 现状与兼容边界

- `main.py` 混合 Tkinter 控件、配置、工具调用和资源处理，应拆开后复用处理逻辑。
- `spine_tools/`、`video_tools.py`、`tool_manager.py` 是可复用基础，现有测试作为回归起点。
- Spine 输入支持任意目录名，输出到 `program/spine`，保留源目录层级。
- UI BG 输出到 `program/bg`，保留原尺寸；UI 包含碎图、字体、艺术字、粒子和视频分类规则。
- 视频输出仍分 `program/video/pc` 与 `mobile`。
- 原格式、WebP、PNG、JPG、Basis 的含义保持一致；Basis 当前输出 `.basis`。
- 当前项目多处使用 Windows 专用工具和进程行为；Tauri 本身支持跨平台不等于本项目已支持 Mac。

输出路径、命名、Atlas 引用和默认选项属于兼容契约。先记录样例基线，再迁移；发现旧版缺陷时记录为有意修复，并添加验证，不能把错误行为当作兼容要求。

## 3. 技术架构

```text
React + TypeScript + Vite
  页面 / 表单 / 翻译 / 任务状态
             │ Tauri commands / events
Tauri 2 + Rust
  文件选择 / 路径校验 / 配置 / 后台进程生命周期
             │ JSON Lines over stdin / stdout
Python worker（随应用打包）
  Spine / UI / 视频处理 / 结构化进度
             │ 参数数组启动子进程
ImageMagick / Basis Universal / TexturePacker / 转换器 / FFmpeg
```

Python worker 使用 PyInstaller 打包为受控 sidecar，不再导入 Tkinter，也不要求用户安装 Python。Rust 只允许启动随包 worker；由用户选择的外部工具路径经验证后作为参数传入。前端不直接拼接 shell 命令，不开放任意命令执行权限。

建议目录（实施时创建）：

```text
frontend/src/
  app/                    # 布局、导航、应用状态
  features/processing/    # 三种资源处理模式
  features/settings/      # 工具、语言、配置
  shared/                 # 控件、事件类型、翻译
src-tauri/                # Rust、窗口和打包配置
backend/
  worker.py               # 任务协议入口
  services/               # 处理编排，禁止依赖 GUI
spine_tools/              # 已有核心逻辑
tests/                   # 后台和协议测试
docs/                    # 设计与验收材料
```

使用现有应用图标。锁定前端、Rust、Python 发布依赖版本，保存锁文件或构建约束，避免开发机和构建机依赖漂移。

## 4. 页面与交互

### 4.1 布局

左侧导航：资源处理、设置；底部放语言、GitHub、版本。资源处理页切换 Spine / UI 图片 / 视频。宽窗口将参数与任务信息并排，窄窗口上下排列，内容可滚动。

统一输入框、下拉框、按钮、间距、焦点和禁用样式。第一版先提供浅色主题。目标最小窗口 960 × 720；在 Windows 100%、125%、150% 缩放下验证关键操作可见或可滚动到达。

### 4.2 资源处理

1. 输入与输出：文件夹选择或拖入，展示实际输出路径。
2. 处理选项：仅显示当前类型相关参数，Spine/UI 格式分别记忆。
3. 工具检查：每项显示就绪、缺失或不可用，以及实际路径和修复入口。
4. 开始处理前：检查参数、目录关系、工具可执行性；明确告知将被清理的目录，并确认执行。
5. 处理中：显示阶段、文件计数、进度和耗时，禁用重复启动，提供取消。
6. 任务结束：成功可打开输出目录；失败显示具体原因、关联文件和建议；支持复制日志。

详细日志默认收起，错误出现时给出可见提示。不能为模拟流畅而伪造百分比；已知文件总数显示真实计数，未知耗时阶段显示阶段状态。

### 4.3 设置

保存语言、工具路径、最近输入输出和各模式参数。默认中文，切换项显示 `中文 / Chinese` 与 `English`。允许重新检测工具、手动指定程序、打开官方下载地址及导入旧配置。

依赖按实际流程计算：例如普通 UI 图集需要 TexturePacker，全部背景图模式不应强制要求它；含视频的 UI 任务需要 FFmpeg。工具检查必须验证对应功能可用，不能仅判断路径存在。

## 5. 任务与通信协议

单次只运行一个处理任务。界面收集参数后生成不可变任务快照；处理中修改设置不能影响已启动任务。

请求至少包含 `protocol_version`、`task_id`、`action`、`options`。支持 `start` 和 `cancel`。事件至少包含：

| 字段 | 用途 |
| --- | --- |
| `protocol_version` | 检查前后端协议是否匹配 |
| `task_id` / `sequence` | 隔离任务与事件顺序，忽略过期事件 |
| `type` | started、stage、progress、log、warning、error、finished |
| `message_key` / `params` | 前端翻译文本及动态参数 |
| `stage_id` / `completed` / `total` | 阶段及实际进度 |
| `status` | finished 中明确 success / failed / cancelled |

事件以 UTF-8 JSON Lines 输出，stdout 只用于协议；诊断和第三方原始输出经捕获后归类到日志。前端支持分片读取和多行拼接，不假设一次读取就是完整事件。

状态机：`idle → checking → running → success / failed`；运行中可进入 `cancelling → cancelled`。预检失败不能清理目录。每个任务只有一个终态；worker 崩溃或退出但没有 finished 时，Rust 必须合成失败事件，恢复界面操作。

取消时由 worker 停止派发后续工作，并清理临时文件；若超时，由 Rust 终止该任务的进程树。Windows 使用受控进程组或 Job Object 管理子进程，不能按程序名称结束其他用户任务。关闭窗口时运行中的任务应提示用户，确认退出后清理任务进程。

## 6. 文件与配置保护

- 始终处理复制到输出位置的资源，不改动源素材。
- 规范化源/目标路径，拒绝源目录位于待清理目录内的情况；UI 和视频同样检查。
- 目录检查需要考虑大小写、符号链接和 Windows junction，避免递归扫描自己的输出或清理源素材。
- 文件冲突先检查再转换；输出失败不删除仍需引用的原纹理。
- 取消或失败不宣称整个输出已回滚；如存在部分输出，应明确标记未完成，并允许打开目录检查。
- 配置使用 Tauri 应用配置目录，带 `schema_version`，采用临时文件加原子替换保存。
- 用户主动选择旧 `config.json` 导入：校验字段、保留可识别选项和工具路径，忽略 `game_name` 等废弃字段；不改写旧文件。
- 新版本与 v1.1.0 分别保存配置；回退使用旧安装包和源素材重新处理，不能承诺恢复已清理的输出。

## 7. 多语言与错误

界面及应用自有消息使用翻译键，覆盖按钮、动态阶段、验证、工具检测、弹窗和任务结果。切换语言后当前状态和应用消息按新语言重新渲染。

第三方工具原始输出保留原文，并显示“原始工具输出”标识。文件名和路径不翻译。错误结构区分工具缺失、启动失败、非零退出、素材缺失、目录冲突、协议错误和取消。

## 9. 打包与发布

在 Windows x64 构建机生成 Python worker，再由 Tauri 打包。安装包包含前端、Rust 主程序、worker、图标和所需运行许可，不包含商业素材、个人配置或第三方资源处理工具。

WebView2 使用 Tauri 支持的安装检测/引导方案；在线安装和离线环境分别验证。未包含离线运行库时明确说明首次安装的联网要求，不能承诺完全离线安装。

发布提供 Windows 安装包、SHA-256、完整中英文说明和已知限制。安装包体积、启动时间和任务耗时以实测记录为准，不承诺比 1.1.0 更小。验证完成前保留旧正式版下载，不覆盖旧标签和附件。

## 10. 主要风险与对策

| 风险 | 对策 |
| --- | --- |
| UI 与处理逻辑耦合导致漏迁移 | M0 建立参数/输出清单，M1 按模式拆分与回归 |
| 后台事件错乱或线程阻塞 | task_id 隔离、顺序编号、缓冲限制、崩溃终态 |
| 取消后留下外部工具进程 | 进程树管理、协作取消加超时终止、故障注入测试 |
| 输出清理影响源文件 | 在所有破坏性操作前统一检查目录关系 |
| sidecar 或 WebView2 在新电脑不可用 | 无 Python 的干净 Windows 环境测试安装和真实任务 |
| 新旧素材处理结果不同 | 相同样例与工具版本比较语义、尺寸、引用及视觉效果 |

## 11. 后续查看器模块

Tauri 中独立加载本地骨骼、Atlas 和纹理，提供动画/皮肤选择、播放暂停、循环、调速、缩放、平移和背景设置。优先评估 Spine 4.2 JSON + PNG/WebP；`.skel`、旧版本及 Basis 单独验证后决定支持范围。

进入查看器开发前确认所选 Spine Runtime 的授权和分发要求。查看器不上传用户素材的设计目标需通过实际网络检查验收。该模块另行建立验收清单，不作为本次 Tauri 迁移的发布门槛。
